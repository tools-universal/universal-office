# Bundled Hunspell dictionaries

Each `<id>.ts` is GENERATED by `scripts/gen.mjs` from the original LibreOffice
files, with the `.aff` and the `.dic` **verbatim** (line by line, only with
template literal escaping), so that it becomes an on-demand chunk (`chunks/`)
in the bundle. The `@license` header of each module carries origin, sha256 and license;
esbuild preserves it (`legalComments`).

Spanish: LibreOffice's `es/` folder only has regional dictionaries (es_AR,
es_ES, es_MX… 23 in total), with no neutral one (RLA-ES's `es_ANY` is not there).
`es_ES` is the one used for all variants, with the id `es` (package
`dictionary-es`): it accepts the general vocabulary, including what is common in Latin America
(*computadora*, *celular*, *carro*), and the *vosotros* forms; it does not have voseo
(*tenés*, *sabés*). Upstream's MPL-1.1 is identical to the `LICENSE-MPL-1.1.txt` here.

## Regenerating / updating

1. Download the originals to `shared/spell/dicts-src/<id>/` (outside git):
   `https://raw.githubusercontent.com/LibreOffice/dictionaries/<commit>/pt_BR/pt_BR.{aff,dic}`,
   `…/en/en_US.{aff,dic}` and `…/es/es_ES.{aff,dic}` (with the READMEs and license
   texts, `…/es/{README_hunspell_es.txt,LICENSE.md,GPLv3.txt,LGPLv3.txt,MPL-1.1.txt}`).
2. Update `UPSTREAM_COMMIT` in `scripts/gen.mjs` and run `npm run gen`.
3. Copy the new READMEs to this folder and run `npm test`.

New dictionary (another language): an entry in `DICTS` of `scripts/gen.mjs`, the
loader in `registerBuiltinSources` (`src/builtin.ts`), the id in
`PUBLISHED_DICTIONARIES` (`src/sources.ts`), the published package in
`packages/dictionary-<lowercase id>/` (package.json with `licenseFiles` + README)
with its entry in `PRODUCTS` of `tools/build-pkg.mjs`, and the license here. Only
dictionaries with an open license.

When published, the dictionaries do not stay in the products: each one is the
`@universal-office/dictionary-<id>` package (see the spell package README, Publishing).
