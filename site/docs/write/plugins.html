Plugins

Plugins extend the editor with custom inlines — atomic objects inside the text (mentions, chips, domain-specific fields) that take part in layout, are drawn by you on the canvas, and survive saving/reopening the .docx.

Model

Plugins are installed per instance (there is no global registry): two <universal-write> instances on the same page can have different sets of plugins. 

editor.use(myPlugin);       // install
editor.unuse('myapp.x');    // remove by id
editor.pluginIds();         // ['universalwrite.mention', ...]

Interface

interface UniversalWritePlugin {
  id: string;  // unique, e.g. 'myapp.chips'
  inlineRenderers?: readonly UniversalWriteInlineRenderer[];
  setup?(context: UniversalWritePluginContext): void | (() => void);  // return = cleanup
}

interface UniversalWriteInlineRenderer<T = unknown> {
  type: string;                    // inline identifier, e.g. 'chip'
  toText?(data: T): string;        // fallback text (export, clipboard, .docx without plugin)
  measure?(ctx): { widthTwips: number; heightTwips?: number };
  draw?(ctx): void;                // draws on the editor canvas
}

measure tells the layout engine how much space the inline occupies (in twips); draw receives the CanvasRenderingContext2D, the position in twips, and the current scale. setup runs on installation and may register listeners on the editor events — return a function for cleanup on unuse().

Example: custom chip

const chips = {
  id: 'myapp.chips',
  inlineRenderers: [{
    type: 'chip',
    toText: (data) => data.name,
    measure: ({ fallbackText, measureText }) => ({
      widthTwips: measureText(fallbackText) + 200,
    }),
    draw: ({ ctx, xTwips, yTwips, scale, fallbackText }) => {
      ctx.fillStyle = '#e8def8';
      ctx.fillRect(xTwips * scale, yTwips * scale, 300 * scale, 100 * scale);
      ctx.fillStyle = '#381e72';
      ctx.fillText(fallbackText, (xTwips + 50) * scale, yTwips * scale);
    },
  }],
  setup: ({ editor }) => {
    const onInput = (e) => { /* react to typing */ };
    editor.addEventListener('uw-input', onInput);
    return () => editor.removeEventListener('uw-input', onInput);
  },
};

editor.use(chips);
editor.insertCustomInline('chip', { name: 'Proposal' });

Persistence in .docx

When saving with save(), each custom inline is serialized as a content control (w:sdt) with its type, data, and fallback text. When reopened in Write, the plugin's renderer is reapplied; when opened in another editor (including the reference app), the fallback text is shown — the document stays readable everywhere.

Ready-made plugin: mentions

The package includes createMentionPlugin: type @ and a suggestions popover appears; on selection, the mention is inserted as an atomic inline. 

import { createMentionPlugin } from '@universal-office-pro/write';

editor.use(createMentionPlugin({
  prefix: '@',
  background: '#dce8ff',
  color: '#174ea6',
  maxSuggestions: 8,
  emptyLabel: 'No people found',
  source: async (query) => {
    const resp = await fetch(`/api/people?q=${encodeURIComponent(query)}`);
    return resp.json();  // [{ id, label }, ...]
  },
}));

Relevant events

EventUse in plugins
uw-before-inputCancelable — intercept typing triggers (like the mention's @).
uw-inputReact to text already inserted (e.g. update the popover search).
uw-custom-inline-insertedNotification that an inline of your type entered the document.
uw-plugin-added / uw-plugin-removedInstallation lifecycle.
