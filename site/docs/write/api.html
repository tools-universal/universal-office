API reference

Public methods and properties of the UniversalWriteElement class (the <universal-write> element), grouped by area.

Built-in chrome (toolbar & status bar)

The component can render its own top toolbar and bottom status bar — no external chrome to wire. They are set via attributes (or the matching properties) and load Material on demand, so the default costs nothing.

Attribute / propertyTypeDescription
topbarboolean attributeTop bar with menus, the Navigation Pane (Ctrl+F), rulers and gridlines (View › Show), find & replace, comments beside the page, open/save (File System Access or the host), autosave, recent files, Protected View, compare, theme, focus/read modes, context menu and drag & drop.
toolbarcompact · ribbonStyle of the top bar: compact (default — File/Edit/View/Insert/Format/Tools/Help menus plus one toolbar row that collapses by priority) or ribbon (tabs, groups with dialog launchers and contextual tabs).
theme · accentauto · light · dark · blackOpt-in Material theme scoped to the element. Without it (and without a choice in View › Theme) the bars inherit color-scheme and --u-color-* from the page.
storage-keystringRemembers this instance's bar choices (toolbar style, theme, comments, autosave) in localStorage; falls back to id, otherwise session-only.
noautosave · nounloadpromptboolean attributesTurn off autosave / the leave-page prompt. Handling the cancelable uw-save-request / uw-open-request events (preventDefault()) hands saving and opening to the host.
bottombarboolean attributeBottom status bar: page/word count, view switch, zoom.
authorstringName recorded on tracked changes and new comments. Without it the bars use the host's user name (host.userName(); Electron: the OS user) or ask once and remember the answer.
 
<universal-write topbar bottombar></universal-write>
<universal-write topbar toolbar="ribbon" bottombar></universal-write>
// or at runtime, via properties
editor.topbar = true;     // boolean
editor.bottombar = true;  // boolean
editor.setAttribute('toolbar', 'ribbon');

// optional: what only the host app can do (e.g. an Electron shell)
editor.host = {
  openFile: () => bridge.open(),                 // { name, bytes, motw? } | null
  saveFile: (bytes, { name, format, saveAs }) => bridge.save(bytes, name),
  setDirty: (dirty, name) => bridge.setDirty(dirty, name),
  windowControlsOverlay: true,                   // frameless window
};

Commands whose editor API does not exist yet stay hidden, so new editor features appear in the bars as soon as their method exists.

The bars are themed with Material Design 3 (theme and accent color are scoped to the element; tune them with --uw-font, --uw-desk, the --uo-* variables or ::part()) and follow light/dark mode, and their controls reflect the current selection (active buttons, current style, font, size, and color).

Styles

The document’s styles.xml is edited in place: each operation rewrites only the w:style elements it touches and leaves the rest byte for byte. New and modified styles are written the way Word writes them (a new paragraph style is linked, with a …Char twin; its id is the name without accents or spaces; a built-in style used for the first time gets Word’s full definition). Built-in names follow the UI language (heading 1 → “Heading 1” / “Título 1”). With topbar, the ribbon’s Styles group is a thumbnail gallery, its launcher opens the Styles pane, and Format › Styles (compact bar) has the pane, the Style Inspector and the Create/Modify Style dialog.

Tables

Tables follow Word’s rules (measured against Word): what each operation does to widths, merges, borders and styles, and what it writes to the file. Every operation is one undo step, works in nested and floating tables and is refused in Protected View. A table read from the file keeps its original XML for everything the operation did not touch (rows, cells, content controls and bookmarks inside it). With topbar: Insert › Table, Format › Table, Tools › Sort (compact bar), the contextual Table Design and Table Layout tabs (ribbon) and the context menu.

Pictures

Pictures follow Word’s rules (measured against Word): the XML each operation writes, the wrap and position it keeps, how effects and adjustments are drawn on the page and in the PDF. Every operation is one undo step and edits only the picture’s own XML. With the mouse: round handles resize (corners keep the aspect ratio when it is locked, Shift inverts, Ctrl from the center), the handle above rotates (Shift: 15° steps), dragging moves (an inline picture moves in the text), arrows nudge a floating picture, Delete removes it. With topbar: the contextual Picture Format tab (Adjust · Picture Styles · Accessibility · Arrange · Size), the compact bar’s Picture group, Format › Picture, the context menu, the Format Picture, Alt Text and Selection panes and the Layout and Compress Pictures dialogs.

Navigation Pane, ruler and gridlines

With topbar, View › Show turns on the Navigation Pane (also Ctrl+F), the Ruler and the Gridlines, as in Word. The pane has a search box and three tabs: Headings (the tree of the body's headings — click to go, collapse/expand, drag a heading to move its whole section, right-click to promote/demote, add, delete or select), Pages (thumbnails) and Results (the matches with the text around them). The heading tree is built like Word's (checked on real documents): the built-in Heading styles count by name even without w:outlineLvl, list numbers and All Caps show as in Word, headings in tables and empty ones are left out. The ruler shows the margins, the section's columns, the table cells, the paragraph's indents and tab stops (centimeters with lang="pt", inches otherwise): drag to change them (0.25 cm or 1/16" steps; Alt = free), click to set a tab, drag a tab off to remove it, double-click for Page Setup, Paragraph or Tabs. Dragging writes what Word writes: only the attributes that differ from the style, tab stops in position order and w:val="clear" for a style's tab that was removed. Gridlines draw the document's drawing grid (9 pt from the margins by default) on screen only.

Header and footer

With topbar, editing a header or footer shows the Header & Footer tab of the ribbon (the compact bar has the same under Insert › Headers & footers): galleries of built-in designs for the header, the footer and page numbers (top or bottom of the page, page margin, current position), Date & Time, Document Info, Go to Header/Footer, Previous/Next, Link to Previous, Different First Page, Different Odd & Even Pages, Show Document Text, the distances from the page edge and Insert Alignment Tab. Each page shows the name of its part (“First Page Header -Section 2-”) and “Same as Previous” when it comes from the previous section. What is written follows Word: unlinking copies the inherited part into a new part of the section (pictures included), linking removes the section's part from the file, page numbers from the galleries are kept in the block Remove Page Numbers finds, Update automatically inserts a TIME field. Text, headers/footers and these options share one undo history; saving keeps the header or footer in editing.

Footnotes and endnotes

Notes are edited in place: clicking the note area (bottom of the page, or the endnotes after the text) enters the note; Esc or a click in the text goes back. Text and notes share one undo history. Deleting a reference deletes its note; the first Backspace right after a reference only selects it; pasting a copied reference creates a new note with a copy of the text. With Track Changes on, a new note is an insertion and a deleted reference keeps its note until the deletion is accepted; revisions inside notes appear in getRevisions() (story: 'footnote' | 'endnote') and in Accept/Reject All. Ctrl+Alt+F / Ctrl+Alt+D insert a footnote / endnote.

Links and references

Bookmarks, cross-references, captions, the table of figures, the table of contents and hyperlinks are written the way Word writes them (bookmark XML and ids, hidden _Ref/_Toc bookmarks, complex REF/PAGEREF/NOTEREF fields, SEQ/STYLEREF captions, multi-paragraph TOC fields). Bookmarks follow edits like Word's: typing at the start of a bookmark goes inside it, at the end it stays out; deleting the whole bookmarked text deletes it; cut and paste moves it, copy does not duplicate it. The layout engine computes REF (exact bookmarked text, \n \r \w \d, \p above/below), NOTEREF, STYLEREF (\s, \n) and SEQ \s n the way Word does when it prints or exports. F9 updates the fields in the selection (Ctrl+A, F9: all); Ctrl+click follows a cross-reference inserted as a hyperlink.

Track changes

With tracking on, typing, deleting, Enter and formatting become revisions with author and date, written as Word writes them (w:ins, w:del, w:rPrChange, w:pPrChange, paragraph marks). The state is saved in the .docx (w:trackRevisions). PDF export and printing follow the markup mode on screen.
