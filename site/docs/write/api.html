API reference

Public methods and properties of the UniversalWriteElement class (the <universal-write> element), grouped by area.

Built-in chrome (toolbar & status bar)

The component can render its own top toolbar and bottom status bar — no external chrome to wire. They are set via attributes (or the matching properties) and load Material on demand, so the default costs nothing.

Attribute / propertyTypeDescription
topbarboolean attributeTop bar with menus, find & replace, comments beside the page, open/save (File System Access or the host), autosave, recent files, Protected View, compare, theme, focus/read modes, context menu and drag & drop.
toolbarcompact · ribbonStyle of the top bar: compact (default — File/Edit/View/Insert/Format/Tools/Help menus plus one toolbar row that collapses by priority) or ribbon (tabs, groups with dialog launchers and contextual tabs).
theme · accentauto · light · dark · blackOpt-in Material theme scoped to the element. Without it (and without a choice in View › Theme) the bars inherit color-scheme and --u-color-* from the page.
storage-keystringRemembers this instance's bar choices (toolbar style, theme, comments, autosave) in localStorage; falls back to id, otherwise session-only.
noautosave · nounloadpromptboolean attributesTurn off autosave / the leave-page prompt. Handling the cancelable uw-save-request / uw-open-request events (preventDefault()) hands saving and opening to the host.
bottombarboolean attributeBottom status bar: page/word count, view switch, zoom.
authorstringName recorded on tracked changes and new comments. Without it the bars use the host's user name (host.userName(); Electron: the OS user) or ask once and remember the answer.
 
<universal-write topbar bottombar></universal-write>
<universal-write topbar toolbar="ribbon" bottombar></universal-write>
// or at runtime, via properties
editor.topbar = true;     // boolean
editor.bottombar = true;  // boolean
editor.setAttribute('toolbar', 'ribbon');

// optional: what only the host app can do (e.g. an Electron shell)
editor.host = {
  openFile: () => bridge.open(),                 // { name, bytes, motw? } | null
  saveFile: (bytes, { name, format, saveAs }) => bridge.save(bytes, name),
  setDirty: (dirty, name) => bridge.setDirty(dirty, name),
  windowControlsOverlay: true,                   // frameless window
};

Commands whose editor API does not exist yet stay hidden, so new editor features appear in the bars as soon as their method exists.

The bars are themed with Material Design 3 (theme and accent color are scoped to the element; tune them with --uw-font, --uw-desk, the --uo-* variables or ::part()) and follow light/dark mode, and their controls reflect the current selection (active buttons, current style, font, size, and color).

Styles

The document’s styles.xml is edited in place: each operation rewrites only the w:style elements it touches and leaves the rest byte for byte. New and modified styles are written the way Word writes them (a new paragraph style is linked, with a …Char twin; its id is the name without accents or spaces; a built-in style used for the first time gets Word’s full definition). Built-in names follow the UI language (heading 1 → “Heading 1” / “Título 1”). With topbar, the ribbon’s Styles group is a thumbnail gallery, its launcher opens the Styles pane, and Format › Styles (compact bar) has the pane, the Style Inspector and the Create/Modify Style dialog.

Tables

Tables follow Word’s rules (measured against Word): what each operation does to widths, merges, borders and styles, and what it writes to the file. Every operation is one undo step, works in nested and floating tables and is refused in Protected View. A table read from the file keeps its original XML for everything the operation did not touch (rows, cells, content controls and bookmarks inside it). With topbar: Insert › Table, Format › Table, Tools › Sort (compact bar), the contextual Table Design and Table Layout tabs (ribbon) and the context menu.

Track changes

With tracking on, typing, deleting, Enter and formatting become revisions with author and date, written as Word writes them (w:ins, w:del, w:rPrChange, w:pPrChange, paragraph marks). The state is saved in the .docx (w:trackRevisions). PDF export and printing follow the markup mode on screen.

Method / propertyDescription
toggleTrackChanges(on?) · isTrackingChanges()Turns Track Changes on/off (without an argument: toggles).
author · hasAuthor()Name recorded on revisions and new comments: the author attribute, the property, or "Author"/"Autor". hasAuthor() tells whether one was given (the built-in bars ask otherwise).
acceptChange({ moveNext = true }) · rejectChange(…)Accepts/rejects the revisions in the selection, or the one at the cursor, then selects the next one (like Word's Accept and Reject buttons). Returns whether something changed.
acceptAllChanges({ shown?, stopTracking? }) · rejectAllChanges(…)All revisions — body, tables, headers and footers — or only those shown (Show Markup types and people). Returns how many were resolved. One undo step.
nextChange() · previousChange()Selects the next/previous revision (wraps around). false if there is none.

acceptRevisionAt(i) · rejectRevisionAt(i) · selectRevision(i)Acts on the i-th item of getRevisions().
